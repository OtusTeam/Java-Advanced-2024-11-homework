![VM_2.png](src%2Fmain%2Fresources%2FVM_2.png)

Теперь у нас только 1000 запросов вместо 2000 из таблицы users, но запрос все-равно занимает много времени,
его можно оптимизировать, чтобы не загружать всех пользователей:

Профилируем еще раз и видим значительный прирост производительности:
![VM_4.png](src%2Fmain%2Fresources%2FVM_4.png)

Запускаем async profiler из IntelliJ IDEA:
![VM_5.png](src%2Fmain%2Fresources%2FVM_5.png)

Из флеймграфа понимает, что нам нужно зайти в RegistrationService.register,
видим, что в самом начале метода неоптимизированный код, который нужно исправить
![VM_6.png](src%2Fmain%2Fresources%2FVM_6.png)

![VM_7.png](src%2Fmain%2Fresources%2FVM_7.png)

Вывод: с помощью visualvm и async profiler были найдены и исправлены проблемы производительности,
связанные с неоптимальным SQL, а также лишним запросом.
